## トップニュース

### oxc の React Compiler が論理代入演算子を扱えるようになる

【oxc】oxc-project/oxc の `main` に、Yagiz Nizipli による「React Compiler で `??=` `||=` `&&=` をサポートする」PR が入った。これまでは lowering で Todo 扱いになり、これらを使うコンポーネントやフックはコンパイル対象から外れていた。

**何が変わる**

- `a ??= b` を `a ?? (a = b)` の形に lower する（`||=` `&&=` も同様）。`LogicalExpression` の value block の仕組みを使う。

**なぜ変えた**

PR 本文によると、upstream の `babel-plugin-react-compiler` も同じ Todo を報告したままで、対応する2本のPR（react/react#36394、#36733）は stale で閉じられた。却下ではなく放置だった、と書かれている。

**何に効く・誰が困る**

oxc の React Compiler 移植を使う場合、この構文を含むコードが最適化の対象に入る。upstream と挙動が分かれる点なので、差分を気にする利用者は注意が要る（影響の大きさは未検証）。

**ここまでの経緯**

- upstream の2本のPR：stale で閉じられた（日付は未確認）。
- 2026-11-09：oxc に対応が入る。

出典: https://github.com/oxc-project/oxc/pull/29137

## 今日の深掘り

### HTML：アップグレード待ちの要素が別 document に adopt されたとき

**選んだ理由**：custom element の registry が document 単位から要素単位へ移ったことで生じた、アルゴリズム上の隙間を埋める修正で、仕様がどう穴を塞ぐかが読める。

**背景**：要素の upgrade は、reaction として queue に積まれてから実行される。その間に別 document へ adopt されると、要素の custom element registry が変わり、null になることがある。（reaction の仕組みと registry の導入経緯は、この号では未調査）

**変更点**：whatwg/html の a044232（2026-11-09）。「upgrade an element」の手順で、これまで無条件に active custom element constructor map[C] へ要素の registry をセットしていた。null のときは HTML element constructor がそれを想定していなかった。修正後は次の2手順になる。

```
If element's custom element registry is null, then remove the surrounding agent's
active custom element constructor map[C].
Otherwise, set ... [C] to element's custom element registry.
```

（`source` の差分より、要約）

エントリを消すと、HTML element constructor は現在のグローバルオブジェクトに結びついた Document の registry にフォールバックする。別のグローバルの registry を持つ document への adopt では、従来どおり upgrade は失敗する。テストは wpt#64915。

**この変更から分かる設計思想**：null を値として埋めず「エントリなし」で表し、既存のフォールバック経路に流す。constructor 側に分岐を足さず、アルゴリズムの受け手を変えない形に収めている。ブラウザ実装への反映は未確認。

出典: https://github.com/whatwg/html/commit/a0442320781555c99544448e30134662bfc39190
