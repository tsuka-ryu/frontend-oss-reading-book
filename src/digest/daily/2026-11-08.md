## トップニュース

### oxc のパーサーに、1日で十数本の「先読みをやめる」最適化が入る

【oxc】oxc-project/oxc の `main` に、2026-11-07（UTC）の1日で `perf(parser)` / `perf(lexer)` のコミットが十数本入った。多くは Boshen によるもので、パーサーが「先読みして、だめなら巻き戻す」処理を減らす方向に揃っている。

**何が変わる**

- 括弧つきアロー関数の判定：括弧の中を一度パラメーターとして読み、後ろに `=>` が来なければ、その結果を括弧式として再利用する（#28862）。巻き戻して2回読むのをやめる。
- 先読みの省略：TypeScript のキーワード型（#28954）、オプショナル呼び出し（#28876）、`await using`（#28960）で、毎回の先読みを省く。
- 字句解析の高速化：空白（#28953）、行コメント（#28878）、エスケープつき文字列（#28907）、正規表現リテラル（#28911）を、まとめて走査する。
- キーワードのハッシュ化から displacement table を外す（#29036、overlookmotel 系の lexer 整理の続き）。

**なぜ変えた**

PR本文には速度の数字がある。#28862 は「対象を絞ったケースで30〜42%短縮、14ファイルのコーパスではほぼ変化なし」とあり、PR本文の自己申告。#29036 は「avx2 で約1%速い」。なお #28862 の本文には「AI-assisted」とある。個々のPRの動機の議論までは読んでいない（不明）。

**何に効く・誰が困る**

- oxlint、oxfmt、oxc-parser を使う人には、パース時間の短縮として効く可能性がある。ただし数字はコーパス次第で、全体への効果は未確認。
- lexer の crate バージョンが `0.0.0` に戻された（#28986）。公開 crate としての扱いが変わるのかは不明。

**ここまでの経緯**

- 2026-11-06：`oxc_formatter_htmlish` の Vue 対応が入る。[11-07 の号](2026-11-07.md)。
- 2026-11-07：パーサー・レキサーの perf が連続してマージされる。
