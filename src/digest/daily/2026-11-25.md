### Svelte に、非公開のセキュリティ修正が2件入る

【Svelte】2026-11-24 に、メンテナーが「Merge commit from fork」という題のコミットを2件 main に入れました。GitHub の非公開アドバイザリ用の fork で作った修正を取り込むときの定型の題です。公開アドバイザリは、確認した時点では見つかりませんでした。

**何が変わる**

- `967218863`：クライアントの `set_attributes` が、`onClick` のように大文字を含むイベントハンドラー名の属性を、SSR と同じく無視する。変更ログは「属性名の大文字小文字の扱いをサーバーとクライアントで揃える」
- `dba8d14bf`：`to_array(value, n)`（配列の分割代入）が、イテラブルでない配列風オブジェクトにも長さ `n` の上限を守る。以前は `Array.from(value)` で全要素を読んでいた

**なぜ変えた**

コミットとテストから分かるのは、片方は SSR とクライアントの不一致の解消、もう片方は長さの上限の遵守、という点だけです。攻撃の筋道、深刻度、影響バージョンは、アドバイザリ未公開のため**不明**です（推測では書きません）。

**何に効く・誰が困る**

利用者はパッチ版の公開を待つ形です。アドバイザリが出た号で脆弱性の節に書きます。

**ここまでの経緯**

- 2026-11-24：2件のコミットが main に入る

出典: https://github.com/sveltejs/svelte/commit/967218863c0565f7677cb86c55efad1a20a732da / https://github.com/sveltejs/svelte/commit/dba8d14bfa2b26e0fdbb03b31f967e37ac185f59

## 今日の深掘り

### oxc：クラス宣言が単文の位置にあると、パーサーは直したのに変換器が落ちる（`#30141`）

選んだ理由は、「エラーを出しつつ構文木は残す」というパーサーの回復方針が、後段に何を押し付けるかが見えるからです。コミットは `b1d3269eb`。コミットメッセージを根拠にし、ソース全体は読めておらず、diff も読んでいません。

**背景**

`if (true) class U { static x = 1 }` のように、クラス宣言が `if` / ラベル / ループの本体にあると「Invalid class declaration」と報告されます。ただしパーサーはクラスを構文木に残して続行します。

**変更点**

- この形を、回復できる誤りから「致命的エラー」に変える
- 理由（本文より）：クラスの変換は、クラスの隣に文を挿入して行う。これは文のリストの中でしか成立しない。単文の位置では挿入が適用されない
- 結果として、デバッグビルドは `statement_injector.rs:206` でパニックして Node ごと落ち、リリースビルドは生成した文を黙って捨てていた

**設計思想**

パーサーが「直してあげる」と、後段は不変条件が壊れた木を受け取ります。回復の範囲は、後段が依存する形を壊さないところまで、という線引きの例です。

出典: https://github.com/oxc-project/oxc/pull/30141

#### Suspense の ping を、中断した描画の async context で実行する
