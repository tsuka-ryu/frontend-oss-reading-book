## トップニュース

### Next.js の Turbopack GC が、安定版を含む全ビルドで既定オンになる

【Next.js】`experimental.turbopackGc` の既定値が、canary 限定から全ビルドに広がった。`false` を指定すれば無効にできる。

**何が変わる**

- 設定が未指定のとき、正規化後の設定で、既定の時間パラメータの GC が常に有効になる。以前は canary のときだけだった（`packages/next/src/server/config.ts`。差分で `isStableBuild` の import が消えている）。
- `true` とオブジェクト形式（`minProgressMs` / `rootTtlMs`）の挙動は変わらない。
- ドキュメントに `v16.5.0` の履歴が足され、dev と build の両方で既定が `true` と書かれた。

**なぜ変えた**

- PR 本文によると、canary では既に既定オンで、16.5 での出荷を予定しているため。
- GC の中身（何を、いつ回収するか）は本文に書かれておらず、この号では不明。

**何に効く・誰が困る**

- 16.5 に上げると、オプトインしていないアプリでも Turbopack の GC が走る。問題が出たら `turbopackGc: false` で戻せる。
- 検証として PR 本文に書かれているのは、`loadConfig` で設定が期待どおりに読めることまで。実行時の挙動や性能の数字は書かれていない。

**ここまでの経緯**

- 同じ日の周辺：`turbo-tasks-backend` の依存エッジを平らな `EdgeSet` に持つ変更（#101489）、プロジェクト終了時にメモリを OS へ早く返す変更（#101589、#101623）が main に入っている。GC の既定化と同じ流れの作業と思われる（推測）。
- 2026-11-13：#101591 が main に入る。

出典: https://github.com/vercel/next.js/pull/101591 （コミット cad154f116）

## 今日の深掘り

### Vite のビルドマニフェストが、ファイルを経由せず `environment.manifest` で読める

選んだ理由：「設定は出力するかどうかだけを決める」という責務の分け方が、Environment API の使われ方をよく表しているため。

**背景**

- `build.manifest` を有効にすると、`.vite/manifest.json` が出力に書かれる。フレームワークは `buildApp` フックの中でそれが欲しいことがあり、ディスクから読み戻していた。

**変更点**（コミット 4db98449a、#23292）

- `BuildEnvironment` に `manifest?: Manifest`（`@experimental`）が足された（`packages/vite/src/node/build.ts`）。
- `manifestPlugin` の先頭にあった `if (!build.manifest) return false` が消えた。プラグインは常に動き、結果を `environment.manifest` に入れる。
- ファイルに書くかどうかは `emitManifestFile = !!build.manifest` で決まる。書かないときは `delete bundle[outPath]` で、出力からファイルだけを外す。
- 出力が複数ある場合は、最後の出力が揃ってから `finalize` する。

```ts
const finalize = (finalManifest: Manifest) => {
  environment.manifest = finalManifest
  if (emitManifestFile) asset.source = JSON.stringify(finalManifest, undefined, 2)
  else delete bundle[outPath]
}
```
（`packages/vite/src/node/plugins/manifest.ts`、コミット 4db98449a）

**設計思想**

- PR 本文は、`OutputBundle` 全体を environment に持たせる案を、メモリが増えすぎるとして退けたと書く。メタデータに絞った整形済みのデータだけを持つ。
- 代償として、`build.manifest` が無効でもマニフェストの計算は毎回走る。コストの数字は PR に書かれていない。

出典: https://github.com/vitejs/vite/pull/23292

## 仕様の変更

### whatwg/html

#### フォームオーナーの更新が、DOMの挿入・削除・移動フックで定義し直される

【HTML】form owner の更新を、挿入・削除・移動・属性変更の各ステップに分けて書き直した。`form` 属性を持つコントロールが切り離されたときの祖先フォームへのフォールバック漏れも直る。新しい form owner を先に計算し、変わらなければ何もしないため、フォーム間の付け替えで無関係なラジオが外れる挙動が変わる。ブラウザは現在、切り離しの場合に無関係なラジオを外しており、意図的に変えるとコミットメッセージにある。
なぜ変えたか：散らばっていた要件を DOM フックに集約し、#10331 を進めるため。
出典: https://github.com/whatwg/html/commit/985d443
